# Incydent: luki w Nginx (nginx2root), 18.11.2026

## Co się stało
18.11.2026 wyszła informacja o kilku poważnych lukach w Nginx, nazwanych nginx2root. Przez niektóre z nich da się przejąć serwer bez logowania. Poprawki są w wersjach 1.30.7 i 1.31.9. Na lab01 mam `nginx/1.28.3 (Ubuntu)`, czyli wersję podatną.

Luki działają tylko przy konkretnych ustawieniach:
- włączone HTTP/2 (dwie najgroźniejsze luki),
- włączone HTTP/3 (QUIC),
- Nginx jako proxy pocztowe (moduł `mail`),
- specyficzna konfiguracja reverse proxy (zmienne w `proxy_pass` + `mirror` lub SSI).

## Sprawdzenie lab01
Chciałem sprawdzić, czy mam włączone któreś z tych ustawień. `nginx -T` wypisuje całą konfigurację, więc przefiltrowałem ją grepem:

```
$ sudo nginx -T | grep -iE 'http2|quic|http3|resolver|mail|stream|alias'
        default_type application/octet-stream;
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
#mail {
    application/octet-stream                         bin exe dll;
    application/octet-stream                         deb;
    application/octet-stream                         dmg;
    application/octet-stream                         iso img;
    application/octet-stream                         msi msp msm;
    video/quicktime                                  mov;
```

Na początku wyglądało to groźnie, ale żadne z tych trafień nie jest prawdziwe:
- `octet-stream` i `quicktime` to typy plików (MIME), grep złapał je przez słowa `stream` i `quic`,
- `#mail {` jest zakomentowane, to przykład, który Ubuntu wstawia domyślnie.

HTTP/2, HTTP/3 ani proxy pocztowego nie mam. Nginx działa tylko na porcie 80 po zwykłym HTTP ([konfiguracja](../../config/lab01/nginx/uptime)), a sam lab01 stoi za NAT-em w VirtualBoxie. Wersja jest podatna, ale moja konfiguracja nie, więc nie musiałem nic wyłączać.

## Co zrobić dalej
- [x] Sprawdzić konfigurację (`nginx -T`)
- [ ] Zaktualizować Nginx, jak Ubuntu wypuści poprawioną paczkę (18.11 jeszcze jej nie było): `sudo apt update && sudo apt full-upgrade`
- [ ] Zrobić restart Nginx (nie reload): `sudo systemctl restart nginx`
- [ ] Sprawdzić wersję: `nginx -v`
- [ ] Zrobić reboot, jeśli zaktualizowało się też jądro

## Czego się nauczyłem
- To, że wersja jest podatna, nie znaczy od razu, że mój serwer jest podatny. Najpierw trzeba sprawdzić, czy w ogóle używam tej funkcji, w której jest luka.
- Wyniki grepa trzeba przeczytać, a nie tylko patrzeć, czy coś wyskoczyło. Tutaj wszystkie trafienia były fałszywe.
- Po aktualizacji samego Nginx trzeba zrobić `restart`. `reload` wczytuje tylko nową konfigurację, a stary program może dalej działać.
- Paczki w Ubuntu dostają poprawki trochę później niż wersje ze strony nginx.org.
- Im mniej rzeczy mam włączonych, tym mniej rzeczy muszę łatać.
